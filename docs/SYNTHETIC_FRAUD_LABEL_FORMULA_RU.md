# Формула синтетической метки мошенничества — текущая v6

Для каждого события `i` генератор независимо выбирает `U_i ~ Uniform[0,1)` и задаёт:

`is_fraud_i = 1{U_i < p(scenario_i)}`.

У четырёх мошеннических сценариев `p=.88`; у законной поездки и крупной покупки `.01`; у законных частых отказов `.02`; у обычного фона `.01`. Например, **только для иллюстрации** при card testing и `U=.20` метка равна 1, а при `U=.97` — 0. Эти случайные значения не выдаются за значения выполненного набора. 12% отрицательного шума внутри мошеннических сценариев и положительный шум в остальных — авторские параметры симулятора, не банковская статистика и не доказательство вины человека.

V6 распределяет все эпизоды по всему 30-дневному окну; возраст нового счёта вычисляется на момент события. Частота за час и отказы за сутки учитывают только **предыдущие** события того же искусственного клиента. Сценарий, ID клиента, время, флаг отказа и метка не поступают в модель. Обученная логистическая оценка не равна `p` генератора; линейные вклады не являются причинным объяснением. При `p=.88` *ожидаемый приблизительный* предел precision в exact-top-k для отбора только мошеннических сценариев около `.88`, но это не строгая граница в конечной выборке.
