# Формула синтетической метки мошенничества — Русский (v4)

## Текущая формула v5-local (текст v4 ниже — исторический)

Уравнение остаётся `is_fraud_i = 1{U_i < p(scenario_i)}`, где независимое `U_i ~ Uniform[0,1)`. Для четырёх мошеннических сценариев теперь `p=.88` (12% отрицательного шума), для `legit_travel` и `legit_large_purchase` — `.01`, для нового `legit_many_declines` — `.02`, для обычного события — `.01` (было `.005`). Новый законный случай планово занимает 2,5% строк, эпизоды по пять: онлайн-электроника, сумма 100–1 800, вероятность отказа .85, нового устройства .50, искусственное распределение country-risk .2/.6/.2. Много прошлых отказов не означает, что каждое событие мошенническое. Всего восемь сценариев, включая normal. Эти числа — параметры симуляции, не доказательства о человеке. Платт пробуется на 20% данных, но отключается, если Brier **и** ECE на валидации не улучшаются; текущая v5-модель использует исходные логистические вероятности. [Результаты v5](MODEL_EVALUATION.md#v5-local-rigor-audit-2026-10-15).

## Историческая формула v4 и примеры

Формула **создаёт метку симуляции**, а не доказывает мошенничество человека. Прежняя формула v3 `Bernoulli(sigmoid(z))` в v4 **не используется**. См.: [English](SYNTHETIC_FRAUD_LABEL_FORMULA_EN.md), [O‘zbek](SYNTHETIC_FRAUD_LABEL_FORMULA_UZ.md), [сценарии](SYNTHETIC_SCENARIOS.md), [оценка](MODEL_EVALUATION.md), [аудит возможностей](FRAUD_DETECTION_CAPABILITIES.md).

Сначала `generate_event_stream(count, seed, start)` назначает каждому эпизоду один из семи сценариев. На каждый из четырёх «мошеннических» сценариев (`account_takeover`, `card_testing`, `mule_cashout`, `new_account_transfer`) приходится планово 1,5% строк. Законная поездка и крупная покупка занимают планово по 2,5%; остальные строки — `normal`. Из-за округления эпизодов фактические доли могут отличаться. Сценарии задают искусственные диапазоны признаков: card testing даёт серию мелких онлайн-платежей и отказов; законная поездка тоже может включать новое устройство и большое расстояние. Точные параметры — в [таблице сценариев](SYNTHETIC_SCENARIOS.md).

Для каждой строки `i` независимо генерируется `U_i ~ Uniform[0,1)`, затем

`is_fraud_i = 1, если U_i < p(scenario_i), иначе 0`.

Для каждого из четырёх мошеннических сценариев `p=0.94`, для двух законных пограничных случаев `p=0.01`, для обычных событий `p=0.005`. Это **авторские параметры симулятора**, не банковская статистика. Пример: при card testing и `U=.20` метка 1 (`.20<.94`), при `U=.97` — 0. Для поездки при `U=.50` метка 0, при `U=.005` — шумовая метка 1. Это учебные примеры применения формулы, **не** утверждение о конкретных случайных значениях выполненного набора. Доля мошенничества в выполненном наборе измеряется отдельно.

`velocity_1h` считает только предшествующие события того же искусственного клиента за час; `prior_declines_24h` — только ранее смоделированные отказы за сутки. Текущее/будущее событие и метка не участвуют. Название сценария и ID клиента не поступают в модель. Логистическая модель изучает **другое** уравнение по десяти признакам и отдельно применяет калибровку Платта; её оценка не равна `p(scenario)` и не является вероятностью для реального банка. Линейные вклады объясняют вычисление оценки, но не причинность. Доверие аналитика должно опираться на происхождение данных, ошибки отложенного теста, человеческую проверку и ограничения, а не на искусственную метку как на реальную истину.
