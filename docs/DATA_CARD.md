# Data card — v6 synthetic customer event stream

**Synthetic data only.** No real bank records, customer identities, payment APIs, card credentials or live transactions are accessed. The app's default development stream has 12,000 January events and a later 3,000-event test. Ten-seed primary evaluation uses development seeds 42–51 and **new**, untouched test seeds 400045–400054. Split is chronological 60/20/20 fit/calibration/validation. [Current evaluation](MODEL_EVALUATION.md); [historical data card](archive/DATA_CARD_V4_V5.md).

Each fraud scenario (`account_takeover`, `card_testing`, `mule_cashout`, `new_account_transfer`) has planned share 1.5% and positive-label probability `.88`. Legitimate travel and large purchase each have 2.5% planned share and `.01` positive-label probability; `legit_many_declines` has 2.5% and `.02`; normal background has `.01`. Every label is a seeded Bernoulli draw, **not** adjudicated fraud. Exact parameters and formulas: [scenarios](SYNTHETIC_SCENARIOS.md), [English](SYNTHETIC_FRAUD_LABEL_FORMULA_EN.md), [Uzbek](SYNTHETIC_FRAUD_LABEL_FORMULA_UZ.md), [Russian](SYNTHETIC_FRAUD_LABEL_FORMULA_RU.md).

V6 distributes *all* scenario episodes across the full 30-day simulated window using stratified random anchors. New-account opening time is set shortly before each `new_account_transfer` episode; `account_age_days` is computed at the event time, including in late validation. Ordinary events before an assigned account's opening are redirected to an existing old account. At default sizes, a test checks every scenario has at least 10 events in fit, calibration, validation and the separate test stream. This fixes the earlier early-window new-account bias, but the purposeful regular spacing itself is artificial.

Synthetic customer IDs, scenario, timestamps, decline flag and label are audit/simulation fields, never model inputs. `velocity_1h` and `prior_declines_24h` count only *preceding* events for the same synthetic customer. No future label is used in a feature. The scoring surface exposes ten typed features without customer identifiers. Real delayed labels, missing events, shared-account graphs, currencies, demographic/fairness factors, privacy consent and operational base rates are not modeled. A public ULB CSV was **not** available under `data/public/`; the opt-in loader was not run on real data in v6.
