# Model card — v6-local synthetic-only risk model

**Primary ten-seed synthetic result:** exact-5% precision **.8313 [.8147,.8487]**, recall **.6689 [.6566,.6799]**; PR-AUC **.7455 [.7219,.7656]** (95% seed-bootstrap CI). Full [evaluation](MODEL_EVALUATION.md) and [historical card](archive/MODEL_CARD_V4_V5.md). No public or real-bank dataset was evaluated. This is not production-ready or a diagnosis of an individual.

The active score is a validation-selected logistic-regression pipeline with one-hot categorical encoding, standardized numeric/derived features, and optional disjoint Platt calibration only when both validation Brier and ECE improve. Seven of ten v6 seeds enabled Platt; a forced-off comparison has the same exact-top-k ranking metrics but may have different probabilities/thresholds. A shallow depth-3 tree is a learned baseline, **not** the deployed explanatory model. The frozen hand rule was authored with generator knowledge and is not independent; external human review is recommended.

Default development split: 7,200 chronological fit, 2,400 calibration, 2,400 validation, then a separately generated 3,000-row later synthetic test with new seed 400045 for the labelled seed-42 example. Candidate and threshold selection never use test labels. Primary results aggregate ten seeds 42–51 / test seeds 400045–400054. The four fraud typologies and artificial labels are described in the [data card](DATA_CARD.md) and [formula](SYNTHETIC_FRAUD_LABEL_FORMULA_EN.md). Per-transaction linear contributions reconstruct the selected logistic log-odds, **not causal reasons** or bank reason codes; hand signals remain separate.

Critical limitations: held-out **card-testing recall .0127 [.0025,.0254]** on a dedicated synthetic stream; generator-coupled features/labels; false positives/negatives; repeated-customer and episode dependence; uncertain calibration outside the simulator; no fairness validation, real analyst feedback or bank shadow testing. Do not block transactions automatically or use this model for real financial decisions.

Model loading still uses `joblib`, which is unsafe for untrusted files. Local SHA256 and HMAC checks run before loading; the HMAC key is now a separate owner-only file outside `data/` (or an explicit `SENTINELAI_HMAC_KEY_FILE` path). This is **not** an externally anchored signature or bank-grade trust root. `skops`, `skl2onnx`, and `onnx` were not installed in the verified environment; replacing the custom `CalibratedLogistic`/`FunctionTransformer` pipeline would require serialization-conversion tests and an artifact migration. No safe-deserialization claim is made.
